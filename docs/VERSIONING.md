# Documentation Versioning

PRD and architecture documentation use semantic versioning:

- **Major**: incompatible scope, product or architectural change.
- **Minor**: new module, requirement, capability or significant expansion.
- **Patch**: corrections, clarification, typo fixes, non-breaking details.

## Version history

| Version | Date | Status | Summary |
|---|---|---|---|
| 1.0.0 | 2026-11-27 | Baseline | Initial PRD for campaign messaging, automation, chatbot/AI, help desk, infrastructure, tech stack and roadmap |

## Change process

1. Edit the document.
2. Add a dated entry in its version history.
3. Increment version according to the change type.
4. Use a commit message describing the update.
5. Keep prior snapshots when a major revision is published (e.g. `PRD-v1.0.md`).
